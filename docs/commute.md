# رفت‌وآمد با Google Maps

بخش رفت‌وآمد از Maps Embed API رسمی گوگل استفاده می‌کند. قبل از ذخیرهٔ آدرس‌ها، نقشهٔ تهران نمایش داده می‌شود؛ پس از ذخیره، مسیر رانندگی خانه و محل کار نمایش داده می‌شود. تعویض جهت، ویرایش و حذف آدرس‌ها حفظ شده‌اند. آدرس‌های قبلی همان کلید ذخیره‌سازی را دارند و نیاز به انتقال ندارند.

## فعال‌سازی

1. در Google Cloud یک پروژه انتخاب کنید و Maps Embed API را فعال کنید. تنظیمات حساب و Billing مورد نیاز را طبق راهنمای Google Cloud تکمیل کنید.
2. یک کلید مرورگری بسازید و API restriction را فقط روی Maps Embed API بگذارید. کلید سرویس سرور را استفاده نکنید.
3. در `.env.local` مقدار زیر را قرار دهید (این فایل را commit نکنید):

```dotenv
WXT_GOOGLE_MAPS_EMBED_KEY=YOUR_BROWSER_KEY
```

4. `npm.cmd run build` را اجرا کنید، افزونهٔ بارگذاری‌شده از `.output/chrome-mv3` را Reload کنید و یک تب جدید باز کنید.
5. محدودیت مبدأ کلید و ارسال Referer را با ID واقعی افزونه آزمایش کنید. مبدأ افزونه از نوع `chrome-extension://` است؛ پذیرش آن توسط محدودیت Website گوگل بدون کلید واقعی تأیید نشده است. اگر محدودیت مبدأ کار نکرد، کلید را بدون محدودیت عمومی منتشر نکنید؛ می‌توان نقشه را روی یک صفحهٔ HTTPS با دامنهٔ تحت کنترل میزبانی کرد و فقط همان دامنه را مجاز کرد.

کلید مرورگری در خروجی افزونه و URL نقشه قابل مشاهده است. هیچ کلید واقعی در مخزن ثبت نشده است. این حالت به Routes API، کلید نشان یا بک‌اند بازار نیاز ندارد.

## رفتار

- نقشه فقط هنگام فعال‌بودن اسلاید و وجود کلید بارگذاری می‌شود. خروج از اسلاید iframe را خارج می‌کند؛ polling پس‌زمینه نداریم.
- مبدأ و مقصد ذخیره‌شده برای نمایش مسیر به گوگل ارسال می‌شوند. تایپ پیش‌نویس فرم درخواست جدیدی ارسال نمی‌کند.
- زمان و مسافت در رابط خود گوگل نمایش داده می‌شوند. دادهٔ iframe خوانده یا به کارت‌های جدا منتقل نمی‌شود؛ انتخاب مختصات با کلیک برای ذخیره در فرم در این حالت وجود ندارد.
- دکمهٔ بارگذاری مجدد، iframe را دوباره می‌سازد. خطای کلید یا نبود مسیر توسط خود گوگل نمایش داده می‌شود؛ به‌دلیل مبدأ متفاوت نمی‌توان محتوای خطای داخل iframe را بررسی کرد.
- لوگو، attribution و کنترل‌های گوگل حفظ می‌شوند. کد JavaScript خارجی در صفحهٔ افزونه تزریق نمی‌شود؛ CSP فقط قاب `https://www.google.com` را مجاز می‌کند.
- فایل‌های قدیمی کلاینت/سرور نشان فعلاً برای استفادهٔ مجدد در مخزن باقی هستند، اما کارت رفت‌وآمد آن‌ها را فراخوانی نمی‌کند.

## بررسی

تست URL شامل نبود کلید، مرکز اولیه، حفظ آدرس فارسی و جلوگیری از تزریق پارامتر است. تست مدل موجود، ترتیب مبدأ و مقصد در هر دو جهت را بررسی می‌کند. نمایش زنده، محدودیت کلید و دسترسی شبکه باید با کلید معتبر داخل Chrome/Edge بررسی شوند؛ موفقیت build به معنی تأیید اتصال زنده نیست.

راهنمای رسمی: https://developers.google.com/maps/documentation/embed/embedding-map
راه‌اندازی: https://developers.google.com/maps/documentation/embed/cloud-setup

## کارت مسیر ذخیره‌شده روی میزکار

وقتی خانه و محل کار معتبر ذخیره شده باشند، اسلاید اصلی جست‌وجو و بوکمارک‌ها یک کارت خلاصهٔ رفت‌وآمد هم نشان می‌دهد. کارت، دو آدرس را نمایش می‌دهد و با دکمهٔ «نمایش و ویرایش مسیر» اسلاید جزئیات مسیر را باز می‌کند. با ویرایش اطلاعات کارت به‌روز و با حذف مسیر پنهان می‌شود. پیش از تنظیم مسیر، کارتی نمایش داده نمی‌شود. این کارت درخواست API یا بارگذاری نقشهٔ اضافه ندارد و به کلید گوگل وابسته نیست.
